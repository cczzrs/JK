# JKRD V5.0.0 更新对照与依据

> 2026-10-19。用户明确授权按“基础规则修订、异步结构存储独立模块、延后处理”三个区域更新 JKRD 到 V5，并明确不批准节点豁免。本文记录本次实际修改，不把原始差异稿整份追认为现行规则。

## 授权与版本范围

- [JKRD](../JKRD.md) 升级为 V5.0.0；输入与参数锁存是对 V4 的明确修订。
- [异步结构存储模块](../logic_units/async-structural-storage-draft.md) 单独整理，仍是设计草稿；已确认业务行为、未定稿细节、既有实验与已知偏差分别标明。
- 环许可/判定、DAG.CARE、定时队列及快照/恢复/格式校验/指纹集中到 JKRD 延后区。本次不启用这些提案，不发布新的快照 format 或指纹。
- V4 的节点表达式、状态分类、传播、引用下限及无环约束继续适用。链式自动延伸属于构建方法；链尾、池节点、停用节点豁免已否决。
- 原文“第 1 到 230 行修改须确认”由本次明确授权覆盖，改为稳定的授权记录，避免行号变动后失去含义。后续修改仍遵守 AGENTS.md。

## 来源、预期行为、位置与核对

本次没有新增或修改执行器。下表的“文档位置”是本次落地位置；既有实验的实现、历史测试及偏差在模块草稿另记，不能把文档核对写成执行器通过测试。

| 来源 → 预期行为 | 文档位置 | 验证依据 / 反例 |
| --- | --- | --- |
| E04、E20–E23、E35–E40 → 各输入任务独立锁存；输入副本是事件型来源 | JKRD 节点分类、参数表、输入算例 | 独立推导：暂停时输入 1、0，复制依次发布 1、0；累计 K 从 0 得 1、1。若都读最新 0 则不符合规则 |
| E35–E36 → 多输入收齐后一次触发，初值不算事件 | JKRD 两个输入算例 | 只有 X0=1 时不输出；之后 X1=0 才得到 1。两路 1 收齐使 K/K 从 0 得 0，一次 send 只产生一个目标任务 |
| E24–E29、归属纠正 → 目标身份决定队列，完整任务后再选 | JKRD FIFO 及执行流程；模块第二节 | Xi/RAM/Qi=1/2/5；RAM 输出仍在 RAM。排队期间新 Xi 不打断当前 EX，但下一个任务优先选 Xi |
| V4 引用规则、本次否决 → 全部现存 Q 无豁免 | JKRD 来源引用；模块第二、四节 | 池 Q 被引用数为 0 应不合法；删除无依赖节点后的容量记录不是 Q；cause/管理线不能补计数 |
| 本次 ACK 确认 → FRAME_OUT 后才有有效保留 q | 模块第五节 | 执行时无资格的 ACK0/1 均忽略；ACK1 后新帧等待自己完成；旧重发完成不得复活旧帧 |
| 本次回收确认 → 满 8 帧、全消费、无依赖才复用 | 模块第四节 | used<8 且空块继续剩余槽；used=8 但有依赖不得复用；安全复用递增世代 |
| 本次环/快照延后 → 不提升历史提案为已启用规则 | JKRD 延后区；V4 历史参考 | 当前保留 DAG；未定新快照格式、未重算或复用 V4 指纹为 V5 |

## 已知实现差异

本次读源确认，现有 [engine.mjs](../../web/async-structural-storage/engine.mjs) 的 `reset` 建立 S/C 和 ACK_READY/ACK1 互引，`_retention` 建立数据 Q 与保持辅助 Q 互引。它的 `validate` 验证引用计数但未拒绝这些多节点环，`_scc` 仅识别与展示。因此“全部符合 V4”不能扩展到整份演示拓扑；本次保留规则并记录差异，没有为迁就演示放开 DAG 或节点豁免。

既有 17 项定向测试和浏览器记录保留原日期与范围，本次不重跑、不扩充其证明范围。失败重试、DAG.CARE、完整快照与消费者迁移均未在本次完成。
