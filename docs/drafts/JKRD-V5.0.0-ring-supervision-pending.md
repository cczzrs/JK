### 环的判定与 DAG.CARE 环监督模块

- 环由 DAG 检查判定：检查全部 Q 来源到引用目标的连接，排除合法的有状态自身引用后，互相可达的多个节点组成的强连通节点组即为一个环；判定不因节点有状态或传播条件过滤而排除连接。
- 允许多节点反馈环，不因有环而拒绝模型；环内 JK 节点的任务进入 `DAG.FIFO`（优先值 3）。异步存储模块节点即使在环中，任务也进入 `RAM.FIFO`（优先值 2）。
- DAG.CARE 环监督模块关注 DAG.FIFO 中的循环节点组，监督或重构 DAG.FIFO 中的执行节点。
- 活环是循环一定次数后、或长等待被触发后就结束的环，是设计依赖的结构。
- 死环指永不终止或永不触发的环，一般不允许存在：先进入定时队列，或被优化掉该结构。
- DAG.CARE 环监督模块与定时队列的具体设计待设计；定时队列的优先值，以及环判定在加载时静态完成还是在存储工厂 RAM.FACTORY 操作后动态重算，尚待确认，见“待设计与待确认事项”。
~~~~

### `ring-classify` · 加载与结构提交后重算 SCC

> 延后处理：下列 ring-* 均为历史设计方向，不启用反馈环、不放宽现行无环约束。 以下保留历史原文。

由完整 Q 引用图计算强连通分量 SCC，排除合法有状态自引用；多节点反馈形成环。加载时判定，RAM 结构事务提交时重新判定。静态图确定环成员，传播过滤不豁免结构上的环。

关联：[`queue-ram`](JKRD-V5.0.0-notes.md#queue-ram)、[`ring-reassign`](#ring-reassign)。

<a id="ring-reassign"></a>

### `ring-reassign` · 阶段一：活跃任务不跨队列迁移

如果结构变更会改变某节点的队列归属，而该节点有 pending 任务或未收齐的到达集合，则拒绝该变更并回滚。只有安全边界的空闲节点可更新归属，避免旧任务顺序与优先级被重排。

关联：[`task-identity`](JKRD-V5.0.0-notes.md#task-identity)、[`transaction-failure`](JKRD-V5.0.0-notes.md#transaction-failure)。

<a id="ring-budget"></a>

### `ring-budget` · DAG 与 RAM 内环共用预算监督

DAG.CARE 对每个 SCC 的连续任务推进计数，包括留在 RAM.FIFO 的环内节点。达到预算即暂停该 SCC 的后续任务；演示预算为 6，可配置。预算只是安全界限，不把长时间运行判为死环。

关联：[`ring-suspend`](#ring-suspend)、[`queue-priority`](JKRD-V5.0.0-notes.md#queue-priority)。

<a id="ring-suspend"></a>

### `ring-suspend` · 挂起 SCC，让低优先任务继续

保留挂起 SCC 的任务、载荷、顺序、到达集合与预算状态，放入监督等待区；挂起期间新形成的该 SCC 任务也进入此区。等待区不参与就绪优先级竞争，其他 SCC 与普通 Qi 任务仍可执行。

关联：[`ring-resume`](#ring-resume)、[`snapshot-runtime`](JKRD-V5.0.0-notes.md#snapshot-runtime)。

<a id="ring-resume"></a>

### `ring-resume` · 显式恢复，不自动删除结构

操作者或明确的控制条件请求恢复，重新校验世代与结构，并为该 SCC 开始下一预算段。监督只暂停与恢复，不能依据超时自动删除节点、取消帧或丢任务；完整快照必须能还原挂起状态。

关联：[`snapshot-runtime`](JKRD-V5.0.0-notes.md#snapshot-runtime)、[`transaction-generation`](JKRD-V5.0.0-notes.md#transaction-generation)。
