候选格式仍采用 `jk-logic-structure-V5.0.0` 和 `jk-logic-runtime-V5.0.0`，**必须同时写 `schema_revision="draft-1"`**。未定稿的提案名不等于正式格式获批；未知版本不能靠改名或补默认字段加载。

- **structure：新运行的结构定义。** 保存当前声明的节点、创建初值、接口、容量、成员、工厂绑定及完整初始化契约；没有 `runtime` 字段。加载仅初始化，不发布事件。不能从带活帧的运行图删掉 `runtime` 就宣称得到有效初始模型。
- **runtime：完整任务边界的运行检查点。** 内嵌当前完整结构，增加全部当前 q、未完任务、到达集合、输入交接、模块进度和分配器。允许 Q 编号有删除后的缺口；不需要重建已经删除的旧业务轮。
- **不增加“丢失上下文但声称可续算”的第三种格式。** 只保存部分状态的数据可以作为报告，不能用这两个格式名表示完整运行检查点。

当前 profile 固定为 `JKRD-V5-DAG-1-2-5`：只有三条已启用队列。`DAG.FIFO`、SCC/预算/定时监督、未提交事务、失败或重试等待区均不属于此 profile；出现这些现场就拒绝导出为本版完整检查点、也拒绝加载，不能悄悄丢弃。环和 F03/F04 后续定稿后再增加明确的格式修订与校验规则。

异步存储部分使用明确版本的模块契约。工厂始终依据节点引用执行**操作事务**；结构中保存操作、参数规则与真实节点绑定，不给 RAM.FACTORY 增加 EX、q、pro 或执行队列。

### 2. 顶层与结构字段

两个格式共用以下外壳；结构文档没有 `runtime`，运行文档必须有它。完整实例见上表，字段不能用省略号导出。

| 字段 | 类型与要求 |
| --- | --- |
| `format` | 两个候选名称之一 |
| `schema_revision` | 固定 `draft-1` |
| `rule_profile` | 固定 `JKRD-V5-DAG-1-2-5` |
| `canonicalization` | 固定 `jk-json-v5-draft-1` |
| `structure` | 下表的完整结构对象 |
| `runtime` | 仅运行文档具有，见后文 |
| `fingerprints` | 必含 `format_md5`、`md5`，均为 32 位小写十六进制 |
| `metadata` | 必含 `name / created_unix_ns / display / provenance`；只存名称、导出时间、展示和审计信息，不参与求值或指纹 |

| `structure` 字段 | 数据及约束 |
| --- | --- |
| `nodes` | `{id,generation,ex_version,ex,pro?}` 数组；按 Q 数字编号升序。generation 与 ex_version 为正十进制字符串；默认 pro 可省略 |
| `initial_q` | 保留 `{"0":[Q...],"1":[Q...]}` 分组，**只表示各现存节点创建初值和状态分类**，不随运行 q 改写 |
| `inputs / outputs` | `{id,external}` 数组；端口编号连续、映射唯一、按 X/Y 位序排列；位宽由数组长度取得 |
| `q_y` | `{output,node:{id,generation}}` 数组；每个 Y 恰好绑定一个合法、传播条件为 `q=0/1` 的 Q |
| `capacity` | `max_live_nodes` 为正十进制字符串或 null；null 表示模型未设总数上限，不承诺无限物理资源 |
| `contracts` | `{id,revision,definition_md5,definition}`；内嵌行为所需的声明式操作、模板、参数规则，按注册契约严格校验，禁止可执行源码 |
| `factories` | 工厂 ID、契约 ID 与有序节点行为绑定；每项绑定保存主 Q 世代/EX 版本、阶段、操作名、参数 |
| `modules` | 模块 ID、契约/工厂身份、完整成员、8 槽配置、固定角色到 Q 的映射及初始化声明；成员决定 RAM 归属 |

Q 数、位宽、来源/操作统计、反向引用和队列归属从这份结构推导，不另存可以独立修改的统计真值。无任意旧的位宽上限被悄悄引入；模块本身仍为 W∈[1,8]。输入前缀 `Q0..Q(N-1)` 不缺失；其后物理编号允许因安全删除而有空洞，本修订选择**不重用物理 Q 编号**，容量与块标识可按世代复用。

所有会改变行为的配置，包括端口、容量约束、成员、模板和操作绑定，均进入结构指纹。`metadata` 不能用来存储实际调度规则、状态或控制参数。工厂契约必须完整嵌入且版本/摘要与消费者支持的语义相符，不能仅凭一个文件路径或操作名字猜测如何恢复；未知契约拒绝续算。A03 的具体绑定仍是待确认方案，格式设计不替它提前批准行为。

### 3. 任务锁存参数统一为一个本地 bit 池

Xi 值、Qi_J0 数据、整帧参数和输出锁存都用同一 `parameters` 表达；不再设置互相可能冲突的 `xi_value / event_values / frame_bits / output_bits` 多份值。`sources` 将 EX 来源映射到池中的位置；`frames` 用索引数组表达该帧的有序视图，数组长度就是 W。

```json
{
  "bits": [1, 0],
  "sources": [
    {"source": {"kind": "Q", "id": "Q0", "generation": "1"}, "index": 0},
    {"source": {"kind": "Q", "id": "Q1", "generation": "1"}, "index": 1}
  ],
  "frames": [
    {
      "frame": {"module_id": "M0", "sequence": "12"},
      "indices": [0, 1],
      "channels": [
        {"kind": "Q", "id": "Q0", "generation": "1"},
        {"kind": "Q", "id": "Q1", "generation": "1"}
      ]
    }
  ]
}
```

这是 S/C 整帧参数片段，不是完整快照。普通输入复制任务同样使用 `bits:[1]`，来源为 `{"kind":"X","id":"X0"}`；没有帧时 `frames:[]`。每个任务独立持有自己的池，不跨任务共享可变载荷；0 是有效 bit，缺值只能由缺字段或缺索引表示并按契约拒绝。

`parameter_policy` 只说明已有规则如何校验，不创建新的锁存机制：

| policy | 必须保存 / 禁止替代 |
| --- | --- |
| `event` | 恰好保存本 EX 的有效 Qi_J0 来源，包括 Xi 输入值及按事件型处理的输入副本数据；普通 Qi_q 来源、目标自身起点在执行时读最新 q，不能在这里冻结 |
| `frame-handoff` | 仅用于已绑定接力协议；实际 W 路、帧身份、sources 与 indices 必须相符。S/C 各持有独立参数，不靠相同帧 ID 代替 bit |
| `output-latched` | 仅用于已绑定模块输出锁存协议；允许按现有输出例外锁存有状态来源，不能推广到普通节点或 H/F/READY 附带 EX |

同一来源只映射一次，EX 重复引用共享该次值；所有索引必须合法。帧通道和 sources 指向同一池值，不能提供不同版本。池中不保留无使用位置的额外 bit；原因、字面量、历史帧身份不能伪装成来源。未来按执行时选择的节点对象不提前绑定，已确定的附带 EX 则须完整保存目标、版本、参数和执行顺序。

### 4. runtime：当前 q、FIFO、到达集合与依赖

| 字段 | 内容 |
| --- | --- |
| `boundary` | 完整边界修订号、最后完成任务、已接收输入序号、已发布输出序号、输入交接/传播已完成；`active_task`、`active_transaction` 必须为 null |
| `q` | `{node:{id,generation},value}`；恰好覆盖 initial_q 的全部有状态成员，一项不多、一项不少 |
| `fifos` | 必须恰好具有 `Xi.FIFO / RAM.FIFO / Qi.FIFO` 三个数组；空队也必须写 `[]`。名称决定归属，任务内不重复保存 queue 或优先值 |
| `arrivals` | 目标完整身份/EX 版本与已到达来源/bit；仅下一组**非空、严格未齐**集合。空集合省略，缺失来源从 EX 推导 |
| `modules` | 与结构中的模块逐一对应的动态现场，见下一节 |
| `allocators` | `next_node / next_task / next_input / next_output` 规范十进制字符串，恢复不重置；序号只标识身份，不重新排序任务 |

任务固定字段为 `id,kind,target,parameter_policy,parameters,behavior_id,bound_ex,protected_reads,context,cause`。`kind` 为 input-copy、node-ex、module-node 或 output-node，全部仍是**真实 Q 的任务**。`bound_ex` 是当前事务计划中已确定的附带求值，不是另一个 FIFO；每项保留 target、policy、parameters 和注册的条件名。条件组只能使用入队前已具备的参数及执行开始读取的既存身份/q，不能把本事务尚未产生的主结果作为条件参数。同组后续步骤沿用同一次决定。当前 A03 的 ACK 在独立 DEC 阶段固定帧，再形成绑定该帧的 ACT；FRAME_OUT 与 ACK 消费均先用旧 F/C 计算 READY，避免读本事务新状态。附带 EX 不递归触发顶层工厂行为。context.operation 仅标记交接上下文；只有真实主任务的 behavior_id 绑定才能调用相应操作。

分配器还须交叉校验：next_task 大于所有已保存任务身份（包括已完成复制项、待输出项及最后完成任务）；next_input/output 分别等于边界已接受/已发布序号加一。next_node 和各模块 next_* 保留历史分配高水位，至少大于当前及保留历史身份，不能删除最高编号后按现存对象缩小计数。模块契约须声明各身份的序号语法及分配命名空间；块复用世代为旧世代加一。未保留的历史无法由现存集合重新推算，恢复直接使用保存的高水位，指纹不证明未知历史。

每次任务有独立 ID，重复目标和相同数据不合并。FIFO 数组顺序是唯一队内顺序；任务 ID 不要求在所有队列之间构成执行顺序。源分类由当前规则及 EX 推导，不能因为输入副本有 initial_q 就漏掉它的事件型参数。

已入队任务与下一组到达集合分别恢复，不能互相补齐、互相覆盖或执行旧任务时清掉新集合。保存边界发现已齐集合却未形成任务，是不一致现场；加载器拒绝，不通过“补发任务”修复。

目标、尚未锁存的实时来源及附带 EX 的身份/版本必须一致。`protected_reads` 显式保存已绑定主/附带 EX 的普通实时 Q 来源及其预期世代/EX 版本，并与实际 EX 和锁存策略核对；不能只在恢复时随意接受来源当前版本。已锁存的输出 R 参数不是普通实时读取依赖，后续 R.q 改变不影响旧输出。管理线和 cause 不补合法引用；`cause` 只是历史原因，可指向已删除对象，不要求重建旧 Q。独立锁存输出只要保有其真实任务目标、所需附带 EX 与载荷，就可不依赖已回收原槽；帧身份历史记录不等于活的槽引用。

### 5. 异步存储现场：复制中途、PRE/POST 与输出

[字段契约](../../assets/v5-snapshot-design/format-contract.json)的 `StorageRuntime` 给出完整字段集合，以下说明谁是数据真值。

| 字段组 | 必需内容与不变量 |
| --- | --- |
| `input_staging` | 未提交 FRAME_IN 的暂态输入。FRAME_IN=0 只清它；不是当前外部 Xi 值，也不能覆盖已接受帧 |
| `handoffs` | 已接受帧的独立 parameters、原复制任务顺序、实际 W 路及 FRAME_IN 复制任务 ID/目标/完成位置、S/C 行为身份。未完成复制必须在 Xi.FIFO 中恰好找到一次，已完成项不再出现 |
| `areas` | PRE、POST 各自块链顺序、块世代、accepted_count、已占槽及实际数据 Q/V/CLAIM 引用、有效帧顺序；slot 的数据位序不可排序 |
| `frontier / rounds` | 当前独立跨轮状态 Q、READY Q、已建立轮的身份和 JOIN/CLAIM/GO/Q7 引用；晚到帧恢复不依赖旧完成事件 |
| `retire_sets / free_blocks` | 待安全回收的候选集合、已释放容量的上次世代；候选不是额外的保护引用，空容量没有仍存活的 Q |
| `output.requests` | 准备请求顺序、真实 K.q 及独立来源 Q 引用；BUSY、许可等只从固定角色 Q 的当前 q 读取 |
| `output.batches` | 每个未清理批次的帧/请求身份、first/replay、W、已发布位前缀、FRAME_OUT 记录、剩余位置到真实任务 ID 的映射；不另存一份长期 bit 数组 |
| `output.retention` | 保留帧身份、有效宽度、固定 H、CACHE_VALID、F、C_ACK、READY 的 Q 引用；有效性仍由对应 JK q 和执行时队首判定 |
| 模块 `allocators` | block/frame/round/request/batch/handoff/retire_set 的后续编号；帧序号永不复用 |

**完整任务边界不等于完整帧复制边界。** 允许 W 个复制任务只完成一部分时保存；handoff 必须保留全部已接受数据和完成记录。最后一个复制任务完成时，一次性形成相邻 S/C 任务并移交独立参数，随后删除 handoff；安全边界不允许“全部复制已完成但还没移交”的半步现场。已交接 S/C 不再依靠 handoff 重建。

PRE/POST 的长期 bit 只在 `runtime.q` 中，READY/CLAIM/BUSY 等控制也只在 q 中。已消费但本世代未满8的块，仍保存已占槽及合法节点，accepted_count 不清零；满8、全部消费且依赖解除后才释放整块，复用时 generation 加一。删除集合内部边随节点一起移除，外部真实依赖仍保护。

输出批次进度是**执行记录**，不能覆盖 q 中的业务许可，也不能用于重新生成 FIFO。若 W=2、首位已发布，现场应当只有第二位和 FRAME_OUT 的剩余任务，恢复不再发布第一位。FRAME_OUT 任务保存自己的标记锁存值、已绑定附带 EX 和实际来源保护。当前 A03 方案中，完整首发数据仍在受保护 B.q，H 以普通参数规则执行 `J0K(B)`；不能把 marker 任务的历史参数注入 H、不能扩展 output-latched 例外，也不能指望已完成的数据任务仍保留旧 bit。

ACK 输入复制及译码请求只锁存本次 ACK 参数，**不保存输入到达时队首作为绑定**。按本次批准，独立 DEC 执行时确定帧和资格，再将实际存在的完整参数绑定到后续 ACT；恢复必须保存 ACT 的 decoded_frame，不能重新转投下一帧。执行时该帧已消费或身份不再匹配则业务动作为空。旧输出批次继续发布自身锁存载荷，旧 FRAME_OUT 不得更新 H 或重新授予资格；新队首仍须完成自己的 FRAME_OUT。

POST 为空也可能有旧重发正在准备。恢复准备请求后仍须遵守“请求队首且 BUSY=0”才能改接/启动，不能因为无活帧就重置 BUSY 或跳过旧请求。

### 6. 保存与恢复协议

保存请求可随时提出，但只在已定义的完整边界取值：当前 EX/RAM 事务、全部传播、已发生事件的入队、当前外部 send 交接全部完成后，选择下一任务之前。首任务尚未开始、任务因参数不足直接结束也有同样边界；不要求 FIFO 空，也不等待未来缺少的来源。

输入接入与保存使用同一宿主边界次序。以 `accepted_input_sequence` 标明切点：切点前已接受输入及其结果必须完整进入检查点；切点后的输入由宿主保留并在恢复后正常接入，不能一半进入暂态、一半留在外部。这个短暂一致性切点不改变连续输入的业务要求。未知的半提交事务不能当成可保存现场。

恢复分为四步，都是本次候选协议：

1. 解析到隔离候选区，检查文本、字段、契约、结构、状态、任务、动态进度及两个指纹；任何失败都不修改现有模型。
2. 根据结构重建派生索引与成员/来源关系，恢复全部有状态当前 q 和已保存任务/集合/模块状态，核对保护依赖与分配器；不重新判断已入队任务是否“现在应触发”。
3. 原子安装完整候选，保持暂停。**零 EX、零新事件、零自动补任务、零 Yi 重放**；不能先按 initial_q 执行初始化再覆盖 q。
4. 宿主明确继续后，从三队列中按原优先级选择队首；新输入按正常独立锁存规则追加。结构文档则创建新运行，从 initial_q 开始且无历史输入/任务。

`published_output_sequence` 只标明模型已发布的界限，不保存或清除外部 Yi 历史。在宿主配合的暂停/恢复中可以保持剩余输出；**外部进程崩溃后的恰好一次投递**还需要宿主输入日志/输出确认协议，不能仅凭检查点序号声称已经解决。该项不改变模型的即时 Yi 发布规则。

### 7. 格式校验与 V4 处理

校验不能由指纹代替，按以下层次分别报告错误：

1. **文本层：** UTF-8，无 BOM；拒绝非法编码、重复对象键、孤立代理码点、尾随内容、NaN/Infinity。重复键须在被普通 JSON 解析覆盖前检查。
2. **字段层：** 按 `format-contract.json` 逐类型检查。除标明 `?` 的字段外全部必填，null 仅在明确允许处有效；未知字段拒绝。metadata 的展示对象可扩展，但不能改变行为；契约 definition/arguments 必须有匹配的注册字段规则，不能作为任意代码容器。
3. **标量层：** bit 仅数值0/1，不接受布尔；数值只用非负安全整数，禁止负零、小数和指数写法。无界序号、世代、版本、时间戳采用无前导零十进制字符串。Q/X/Y 标识无前导零。没有隐式截断或精度转换。
4. **结构层：** 当前 JKRD 的输入同号副本、EX/pro、initial_q 分类、q_y、非自身来源/使用者下限和全 Q DAG 一项不少；无节点豁免。动态编号缺口合法，悬空引用不合法。
5. **现场层：** 当前 q 覆盖、世代/版本、成员、队列归属、锁存来源、未齐集合、handoff 所有权、槽/帧顺序、输出剩余任务及 ACK 资格一致；普通状态来源不得误冻结，历史原因不得误作活依赖。
6. **能力和指纹层：** 精确支持 profile、契约及修订；复算契约 definition 摘要和两个文档摘要。不得因摘要匹配跳过前五层。

数组分两类：节点、成员、来源集合等表按规定编号顺序导出并校验；FIFO、bit、块槽链、准备请求及输出位置保留业务次序。规范化器不能代替格式校验去重、重排或修复。缺字段不默认为空队列。

V4 文件不能直接作为 V5 runtime 加载。旧 Xi 任务没有本次锁存 bit、未齐集合缺失、initial_q 可能已被保存 q 覆盖，也没有动态/输出完整进度；这些信息不能从当前 q 猜回。允许另行明确选择“导入为新的结构运行”：先验证 V4 原件，提取可用结构，明确采用旧保存 q 作为新初值，丢弃旧任务上下文并记录迁移报告，重新计算 V5 指纹。它是新运行，不是旧执行的无损继续；原文件和旧指纹保留。

### 8. 规范 JSON 与双指纹

规范化版本为 `jk-json-v5-draft-1`：

- 对象键递归按 Unicode 标量顺序排序，不能依赖 JavaScript 默认 UTF-16 排序；数组完全保序。
- UTF-8，无 BOM、缩进、额外空白或尾换行；字符串不做 Unicode 归一化，不删 EX 字符。
- 双引号和反斜杠转义；控制字符使用 `\b / \f / \n / \r / \t`，其余 U+0000–001F 使用小写 `\u00xx`；其余合法 Unicode 标量直接编码，斜杠不转义。
- **唯一默认值归一化：** 删除 `structure.nodes[*].pro` 中显式的 `q=0/1`。不补其他字段，不重排数组，不删除任何其它路径中的同名字段。

```text
F = {
  domain: "jk-v5-format-draft-1",
  schema_revision, rule_profile, canonicalization,
  structure: normalized_structure
}
M = {
  domain: "jk-v5-document-draft-1",
  format,
  format_payload: F,
  runtime: 运行文档的完整runtime；结构文档固定null
}
format_md5 = MD5(UTF8(Canonical(F)))
md5        = MD5(UTF8(Canonical(M)))
```

这里的 F 是完整字段对象，不是把 format_md5 字符串拼入 M。根 `metadata` 和 `fingerprints` 不进入载荷；除此之外所有行为字段都参与。每个 `Contract.definition_md5` 另外按相同规范字节计算，并连同完整 definition 一起进入 F。

本轮调整了历史双指纹的分工：`format_md5` 标识**结构、创建初值及行为契约**，同一结构的 structure/runtime 文档相同；`md5` 再区分文档种类与完整运行现场。改变当前 q、任务、到达集合或模块进度只改变 md5；改变成员、EX、initial_q、接口、容量或绑定会影响二者。时间与展示修改均不改变二者。指纹只检查指定载荷身份，不证明功能、续算等价或文件来源可信。

| 完整设计例 | format_md5 | md5 |
| --- | --- | --- |
| structure-example | `51a1ef11e72009f4b0cfcebdad51822f` | `7a24648abe5ceda22f05e2b4a7c1cda2` |
| runtime-example | `51a1ef11e72009f4b0cfcebdad51822f` | `e6e30387f62e62102cb0672e413ae351` |

两组载荷分别为 633/738 字节及 633/2794 字节；已用 Python hashlib 与系统 OpenSSL 对相同规范字节独立计算，摘要相同。另有6个最小字节向量，并核对展示变化、显式默认pro、当前q、任务bit、任务次序及接口映射的摘要变化符合载荷范围；这些实算只验证载荷/摘要，不执行任何 EX 或恢复任务。

CP2 保存了一个真实的、非空的目标到达集合。恢复应保留已到达的来源身份与数据，不能清空、补造缺项或提前加入 LATCH 任务。CP3 区分“已产生并锁存的 COMP 结果”与“尚未执行的保存事务”；CP4保存实际已译码、已绑定但未执行的两个ACT；CP5区分“业务准备请求、待执行领取门”与“已经开始的准备”。这些差别直接对应全部实际参数就绪的入队规则。CP4有98个现存Q，其中94个有状态；ACK节点Q161–Q164、Q171–Q174仍存活，Q9=Q49=1，A/Q51版本为9。T47/T48保留各自的 `operation_parameters.bound_frame`、真实锁存参数、附带EX和完整planned_creations，不能把这些操作参数留到恢复后重新猜测。

**外部输入时点：** 第一帧在T1前接受；第二帧在T15后、T16前接受，形成T19/T20/T21；ACK0与ACK1在T38后相邻接受；提前ACK0在T56后、T57前接受，形成T60。CP4的ACK复制及译码已经完成，保存的是两个绑定帧1的ACT任务；CP5保存提前ACK的Xi任务T60。恢复不能重新提交这些输入或重新译码CP4的ACK。未发生的未来输入不写进快照FIFO；条件续算以这份显式输入计划为前提。

```text
T1…T15 → T19,T20,T21 → T16,T17,T18 → T22…T56
→ T60 → T57,T58,T59 → T61…T75
```

这里的省略区间表示逐号执行；完整逐项列表保存在推导 JSON。任务ID表示分配顺序，Xi优先造成上述两处插入；其余实际任务归 RAM.FIFO，Qi.FIFO为空，没有新增输出执行队列。

| 帧2首发 | T73/T74/T75：`Y0=1 → Y1=1 → Y8=1` | T75原子建立帧2H及资格 |

CP3剩余输出从Y1开始，CP5剩余输出为 `Y1=0,Y8=0,Y0=1,Y1=1,Y8=1`；CP6无自动输出。恢复不重放已发前缀。此轨迹未在旧输出任务执行前覆盖R，因此它自身不能用来证明所有“误读当前R”错误都被识别；输出独立锁存的反例要求仍保留。

ACK 本次批准的差异已进入 JSON：每个 DEC 执行时确定当时帧和资格，真实允许事件触发该帧的 ACT。T43/T46分别译出允许重发/消费，T47/T48分别执行独立动作；ACT不读取自己新计算的q决定业务，也不把陈旧帧重新绑定到下一帧。提前ACK在T63/T64译码时READY=0，直接忽略。新FRAME_OUT以前的ACK0/ACK1都不等待未来资格。

FRAME_OUT与消费的READY EX为 `J0K1K(F)K(C_ACK)`，先读已有旧状态，再独立改变F或C_ACK，避免旧候选的事务内前序结果依赖。A/A_READ只保留真实引用锚，未执行数据校验；READY观察Q100/Q125各产生一个实际任务并保留依赖。CLAIM保持EX真实引用PRE.V，静默/旧槽/待回收节点均不获得引用豁免。

LATCH临时目标的删除发生在主EX、附带EX和最后读取都结束后的最终原子提交；LATCH静默且无待发布事件，所有外部依赖必须已解除，否则转交后续GC。快照不保存活动EX内的删除或半完成片段。此候选细化替代旧模块第10.6节覆盖整个事务的当前目标删除禁令；旧业务计算轮仍后续GC，现存节点没有引用豁免。

## 快照与校验

### 快照字段与恢复范围

快照保存可加载的节点结构、指定有状态节点的已保存 q，以及 `FIFOS` 中的待执行任务。`initial_q` 同时决定有状态节点集合并保存其初始化值或最近一次完整 EX 已提交的状态，加载后作为起始状态；`q_y` 保存外部 Yi 与 Q 节点的事件和数据绑定。快照同时记录接口配置，不表示模型执行外部输入输出任务，接口要求见“send 输入 Xi 和 输出 Yi 的事件与数据要求”。

| 字段组 | 含义 |
| --- | --- |
| name | 快照名称，不参与计算语义或指纹 |
| format | 当前格式固定为 `jk-logic-structure-V4.0.0`，用于识别本节定义的结构与指纹规则 |
| nodes | 连续编号 Q0 至 Qn 的 id、ex 及可选 pro，按 Q 数字编号排序；默认传播条件规范化为省略，非默认值保留 |
| initial_q | 按 q 为 0、1 分组的有状态 Q，各数组按编号排序；每个成员恰好出现一次，未列入的 Q 为无状态 |
| q_y | 外部输出绑定配置，按 Y 编号排列，每个 Yi 绑定一个已有且传播条件为 q=0/1 的 Q |
| FIFOS | 按队列名称保存 Xi.FIFO、Qi.FIFO 的有序任务，每个任务写为 `{目标Q: {锁存的Qi_J0来源Q: 值}}`；无锁存数据时值为 `{}` |
| inputs 和 outputs | 外部有序 X 和 Y 端口的身份映射 |
| input_bits 和 output_bits | 外部输入输出位宽，当前标准快照各不超过 216 |
| jk_bits 和 jk_bits_max | `jk_bits=nodes.length`，且不超过 `jk_bits_max`；输入副本计入节点总数 |
| ex_source_max 和 ex_source_sum | 各节点引用数量 ex_source 的最大值及总和；每个节点内对来源去重并排除自身，跨节点不再去重 |
| ex_operation_max 和 ex_operation_sum | 单节点最多及全模型的 J/K 操作单元数量 |
| format_md5 | format、nodes、initial_q、q_y 的规范化指纹，包含有状态 q 的保存值 |
| md5 | 在 format_md5 对应字段的基础上，再包含 FIFOS、created_at 的规范化指纹 |
| created_at | UTC（协调世界时）日期小时与 Unix 纳秒时间戳组成的生成标记，参与 md5 |
| display | 展示配置对象，当前用字符串字段 show 保存展示方式；示例为 `{"show": "5D"}`，不改变计算语义或指纹 |

| 恢复范围 | 标准快照的处理 |
| --- | --- |
| 节点结构与有状态 q | 保存并恢复，包括每个 Xi 对应的同编号有状态输入副本 |
| 外部 Xi 当前值、无状态 Q 运行结果、未收齐的 Qi_J0 到达集合 | 不保存 |
| 计算队列组的待执行任务、各队列顺序及任务携带的 Qi_J0 锁存数据 | 通过 FIFOS 保存并恢复，保留重复任务 |
| 执行中的 EX 参数与累加中间值 | 不保存；等待当前任务及完整 EX、全部传播和当前输入更新入队结束后再保存 |
| 外部 Yi 已发生的输出事件历史 | 不保存，不重放；不清空外部系统已有历史 |
| 加载后的动作 | 恢复结构、指定状态及保存的任务，不提前执行 J0、输入复制或其他 EX，不自动发布 Qi 事件，也不执行外部输入输出任务 |

- 快照必须包含同编号有状态输入副本及合法的 Yi 绑定，加载后的运行遵循本文的输入、FIFO 队列组与输出规则。
- 保存请求到来时，等待当前任务及其完整 EX、全部结果传播、当前外部 send 的全部输入更新和相关 Qi 任务入队结束，再保存同一边界的节点状态与 FIFOS，保存完成后才能选择下一任务。
- 保存不要求队列为空，也不等待尚未到达的 Qi_J0 来源；尚未开始首个任务时，以及输入复制任务因 Xi 不可读而结束后，同样在选择下一任务前处理保存请求。
- 保存边界必须一致，不能把不同时间取得的节点状态与队列拼成一份快照；本节规定保存边界，不额外保存执行中间值。
- 标准快照恢复已保存的队列任务，但不保存 Xi 当前值和未收齐的 Qi_J0 到达集合，因此不保证与未中断运行产生相同的后续任务和输出；完整运行现场恢复须另行定义。
- 快照恢复时，模型的 Qi 计算队列组按 FIFOS 还原，Qi_J0 到达集合从空开始，下游可读取输入副本恢复后的 q；外部 Xi 的可读数据及 Yi 的历史不由模型恢复，按输入输出章节衔接。
- 快照恢复后的任务仍按队列优先级与队内顺序处理，不重新判断触发条件；含 Qi_J0 参数的任务使用自身已恢复的锁存数据，不等待这些来源再次产生事件。
- 快照恢复的输入复制任务若在出队时无法读取对应 Xi，就结束本次任务，不执行 EX；之后收到新输入时，按正常输入规则生成新的复制任务。
- 本节定义现行静态快照的字段与恢复范围；动态结构及其保存恢复要求集中在“扩展设计与结构示例”。

#### FIFOS 队列任务字段

- FIFOS 是以队列名称为键的对象，当前必须包含 `Xi.FIFO` 和 `Qi.FIFO`；每条队列用数组保存任务，第一个元素为队首，空队列保存为 `[]`。
- 每个任务是恰好含一个目标 Q 键的对象，键对应的值是该任务的 Qi_J0 锁存数据对象；例如 `{"Q4": {"Q2": 1, "Q3": 0}}`，无 Qi_J0 参数时写为 `{"Q2": {}}`。
- 任务锁存数据的键为来源 Q 编号，值只能为 0 或 1；必须恰好包含目标 EX 全部不同的 Qi_J0 来源，不含 Xi、有状态来源或未引用的来源。
- Xi.FIFO 只保存输入副本任务，其锁存数据对象固定为空；Qi.FIFO 只保存其他节点的任务，恢复时保持队列归属、数组顺序和重复任务。
- 相同目标的每次任务各占一个数组元素，不按目标 Q 合并；`[{"Q0": {}}, {"Q0": {}}]` 表示两个独立任务。
- FIFOS 不保存 Xi 当前值，也不复制有状态来源的 q；有状态 q 仍由 initial_q 保存，任务执行时读取来源最新 q。
- 未收齐的 Qi_J0 到达集合不写入 FIFOS；恢复任务携带的锁存数据只属于该任务，不能用它补充恢复后从空开始的到达集合。
- 队列优先值不作为可修改的快照字段，Xi.FIFO 固定为 1，Qi.FIFO 固定为 5；JSON 对象键排列不表示队列优先级。
- 新队列的名称、任务归属与不同于已有队列的固定优先值，在新增该队列时一并定义；当前格式不接受未定义的队列。

### 统计与快照指纹

- `ex_source` 就是节点的引用数量：统计其 ex 中不同的 Xi 和 Q 来源，排除节点自身，不计常量 0、1，同一来源重复使用只计 1 个。
- `ex_source_max` 为所有节点 `ex_source` 的最大值，`ex_source_sum` 为所有节点 `ex_source` 的总和；同一来源被不同节点引用时，在各引用节点中分别计数，不对全模型的来源再次去重。
- 例如 Q2 的 ex 为 `J0K(Q0)K(Q0)J(Q1)` 时，来源为 Q0、Q1，`ex_source` 为 2；重复使用 Q0 的操作仍执行，J/K 操作单元数量 `ex_operation` 为 4。
- `q_y` 绑定计入所绑定 Q 的被引用数量，不计入其 `ex_source`，也不增加 `ex_source_max` 或 `ex_source_sum`。
- 统计字段由实际结构计算，不能把显示统计误当成 EX 的固定长度限制。
- 指纹载荷的规范 JSON（JavaScript Object Notation，JavaScript 对象表示法）采用 UTF-8（Unicode 字符的 8 位编码格式）；递归按对象键排序，键值及元素分隔符分别为 `:` 和 `,`，不添加排版空格、换行或末尾换行，非 ASCII（American Standard Code for Information Interchange，美国信息交换标准代码）字符直接编码，不转义为 Unicode 编号。
- 字符串内容保持原值，不删除 ex 内部字符；数组保留各自规定顺序，尤其 FIFOS 中的任务数组不得排序、合并或去重；可读导出文件另按示例缩进。
- MD5（消息摘要算法第五版）用于计算下列两个指纹，结果写为 32 位小写十六进制字符串，不能替代功能验证。
- 公式中的字段组合表示建立包含这些字段名及对应值的 JSON 对象，再对该对象的规范 JSON 字节计算指纹；不是直接拼接字段值字符串，也不是把 format_md5 字符串拼入 md5。

```text
normalized_nodes = nodes 省略显式 pro="q=0/1"，保留非默认 pro
format_payload = {format, nodes: normalized_nodes, initial_q, q_y}
snapshot_payload = {format, nodes: normalized_nodes, initial_q, q_y, FIFOS, created_at}

format_md5 = MD5(format_payload 的规范 JSON 字节)
md5 = MD5(snapshot_payload 的规范 JSON 字节)
```

| 变化内容 | format_md5 | md5 |
| --- | --- | --- |
| format、nodes、initial_q 或 q_y | 纳入指纹计算 | 纳入指纹计算 |
| 同一有状态成员的保存值从 0 变为 1 或从 1 变为 0 | 纳入指纹计算 | 纳入指纹计算 |
| FIFOS 的任务数量、队内顺序、目标或锁存数据 | 不参与 | 纳入指纹计算 |
| created_at | 不参与 | 纳入指纹计算 |
| name、display、端口映射、位宽、容量及统计字段 | 不参与 | 不参与 |

- format_md5 包含 initial_q 的成员及其实际 0/1 保存值，不能用作忽略状态值的纯连接结构指纹；默认 pro 的省略与显式 `q=0/1` 按同一规范化结果计算。
- md5 在前一组字段的基础上增加 FIFOS 和 created_at；两组载荷均不包含 md5、format_md5 字段本身，不额外加入派生的有状态成员集合。
- 指纹只覆盖公式列出的字段，不代表整份 JSON 文件的每个字节；没有参与指纹的字段仍须通过各自的结构和数值校验。
- created_at 使用 `YYYY-MM-DDTHH:<Unix纳秒时间戳>` 字符串，两部分必须对应同一 UTC 时刻；示例的 `2026-10-08T00:1791417600000000000` 对应 `2026-10-08T00:00:00Z`，纳秒部分保持字符串以避免整数精度丢失。

#### 格式校验与旧快照处理

- 当前完整快照按下方示例的顶层字段集合保存；节点对象仅允许 id、ex 及可选 pro，initial_q 必须包含 "0"、"1" 两组。
- 已定义对象不接受未定义字段；展示配置集中放在 display，不放入 nodes，也不改变节点状态分类、EX 求值、传播或队列规则；show 的具体展示效果由展示层解释。
- 当前格式不兼容旧快照，也不修改旧快照内容；旧版本、旧字段及旧指纹均不能通过补字段、改名或重算指纹自动转换后加载。
- format 必须为 `jk-logic-structure-V4.0.0`；缺少 FIFOS、使用旧 propagation 字段或旧任务包装结构的快照均拒绝，不把缺失队列默认成空队列。
- 加载前须按本文公式分别核对两个指纹，并完成全部结构、状态、引用、队列及统计校验；指纹匹配不能豁免其他规则。
- 历史模型、报告和附件保留原始内容，本节更新不表示消费者执行器已支持当前格式。

### 结构校验与功能验证

| 校验对象 | 必须满足的条件 |
| --- | --- |
| 格式与字段 | format 为当前 V4.0.0 标记，字段及类型符合本节定义，不接受旧格式或未定义字段 |
| 表达式 | 合法操作单元、非空、扁平无嵌套、引用范围合法，不允许纯字面量节点 |
| 状态分类 | 仅依据 initial_q，拒绝重复或冲突初始化；无状态节点的 EX 必须以 J0 开头且不得显式引用自己；有状态节点可以显式引用自己，但自身结果不触发自身 |
| 输入副本 | 每个 Xi 恰有一个同编号有状态 Qi，EX 为 J0K(Xi)，并在 initial_q 中恰好声明一次；其他节点不得直接引用 Xi |
| Qi 传播与外部绑定 | pro 仅为本文四种传播条件；无状态节点不得采用 q=；外部 Yi 只能绑定默认或显式 q=0/1 的已有 Q |
| 节点、外部接口配置与统计 | 节点连续编号及规定顺序；inputs 数量与 input_bits 一致，outputs 和 q_y 数量与 output_bits 一致，各端口编号与映射合法；节点容量及各统计值符合实际结构 |
| FIFOS 队列任务 | 两条队列均存在，每个任务只有一个合法目标 Q 键且归属正确；值为恰好覆盖所需 Qi_J0 来源的 0/1 数据对象，无此类来源时为空对象；保留顺序和重复项，优先值唯一且固定 |
| 快照指纹 | 按本文字段组合、规范化方式与公式分别校验 format_md5 和 md5；不以旧指纹代替 |
| 引用与被引用数量 | 每个 Q 节点的 ex_source ≥ 1，被引用数量 ≥ 1；引用来源按节点去重并排除自身，被引用数量包含不同其他 Q 的引用与不同 Yi 的 q_y 绑定，自引用不计数 |
| Q 来源连接与循环 | 检查全部 Q 来源到目标的连接；仅排除合法有状态自引用，其余必须形成 DAG（Directed Acyclic Graph，有向无环图），不因状态分类或传播过滤而豁免 |

- 结构合法只说明符合结构约束，目标功能还须通过参考输入、任务执行过程和实际输出事件序列验证。

#### 快照恢复后的输入与输出示例

以下使用“快照 JSON 示例”中的结构、Qi 状态及任务数组，展示外部输入输出与恢复后 Qi 任务的关系。

- 仅凭示例快照恢复、外部尚未提供可读 X0 时，两个 Q0 输入复制任务依次结束，均不执行 EX，Q0 保持恢复值；随后 Q4 使用任务携带的 Q2=1、Q3=0 和执行开始时 Q0=0 求值，得到 0 并发布结果事件，外部 Y0 接收当次数据并输出一次 0。
- 接着 Q2 使用 Q0=0 求值，结果为 0，不满足自身 pro="q=1"，因此不传播事件；所有队列清空，不再产生新输出。
- 若恢复后、处理队列前提交 X0=0，则两个已恢复任务及本次新生成的 Q0 任务均保留，执行时各自读取有效值 0 并正常完成复制；不会因为值为 0 而结束并跳过 EX。
