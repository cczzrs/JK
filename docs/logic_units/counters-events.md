# JK计数器与事件组合

> 现行主源：本地 JK 项目。2026-10-03 从 JK 空间迁入；原文、块元数据与来源版本保存在 provenance。后续规则在本项目维护。原有历史验证日期与范围保持不变。

本页收录 2bit 与 8bit 计数器、按进位传播的局部计算、前后值判定及计算与状态分离模式。规则依据为 [JK规则与设计](JKRD.md)。2026年10月1日按现行规则补充定向验证，区分可运行小例子、历史提案与待实现模式。

下列所有 `q=` 均为永不传播，只用于有状态节点。省略传播条件时为 `q=0/1`。表中“无状态”指未列入 `initial_q`，不是仅凭 EX 开头判断。参考设计中的 `publication` 是临时 JSON 字段，尚不是原生快照已批准编码。

## 全量计数器：保留作为基线

输入 `X0=1` 每次到达加 1，`X0=0` 保持；相同值重复发送也分别执行。输出低位在前，每次单一 X0 事件处理完毕后读取整个计数值。

### 2bit、3 节点、模 4

| 节点 | 初值 / 状态 | EX | 传播 |
| --- | --- | --- | --- |
| Q0 | 无状态 | `J0K(X0)` | q=0/1 |
| Q1，高位 | 0 | `K(Q1)K(Q2)J(Q0)K(Q1)` | q=0/1 |
| Q2，低位 | 0 | `K(Q0)` | q=0/1 |

`initial_q={"0":["Q1","Q2"],"1":[]}`；`q_y=[{"Y0":"Q2"},{"Y1":"Q1"}]`。

同一 Q0 事件先通知 Q1，再通知 Q2，因而高位读取更新前的低位。两位每条输入均计算，即使输入 0 或某位没变。

### 8bit、9 节点、模 256

Q0 为无状态 `J0K(X0)`；Q1..Q8 为状态位，初始全部 0，Q8 是最低位，Q1 是最高位。全部采用 `q=0/1`。

```text
Q0 J0K(X0)
Q1 K(Q1)K(Q2)J(Q3)J(Q4)J(Q5)J(Q6)J(Q7)J(Q8)J(Q0)K(Q1)
Q2 K(Q2)K(Q3)J(Q4)J(Q5)J(Q6)J(Q7)J(Q8)J(Q0)K(Q2)
Q3 K(Q3)K(Q4)J(Q5)J(Q6)J(Q7)J(Q8)J(Q0)K(Q3)
Q4 K(Q4)K(Q5)J(Q6)J(Q7)J(Q8)J(Q0)K(Q4)
Q5 K(Q5)K(Q6)J(Q7)J(Q8)J(Q0)K(Q5)
Q6 K(Q6)K(Q7)J(Q8)J(Q0)K(Q6)
Q7 K(Q7)K(Q8)J(Q0)K(Q7)
Q8 K(Q0)
```

`Yi→Q(8-i)`。Q1..Q8 按高位到低位计算，各高位使用低位旧状态。连续加 1 共 256 次时，8 个输出节点合计执行 2048 次；所有位每轮计算的行为是这个基线的明确性质。

原设计、快照及报告收录于本页附件中的 counter-2bit 与 counter-8bit 目录。原报告是在当时 JKGroup 运行时下生成，不能自动代表现行规则兼容性。本次另外用规则 Page 序列 88 的独立参考执行器重核 2bit 全 8 条、8bit 全 512 条状态转换，均得到 `(count+X0) mod 2^width`，并确认每轮全量输出计算。该补验仍限于每条输入排空后再输入下一条。

## 稀疏进位：区分旧提案与现行规则构造

### 旧方案：计算前按到达值选择目标激活

历史 8 节点方案是：Q0 `K(X0)`；Qi `K1K(Q(i-1))`。额外 `activation_conditions` 指定 X0=1 才激活 Q0，来源低位值为 0 才激活下一位。这些条件在 **目标 EX 执行前** 判断。

该方案保留在附件的 counter-8bit-sparse 目录中，测试器为独立 `ConditionalCounterPrototype`。原报告明确 `current_JK_NET_supports_this_proposal=false`。其数值 / 稀疏验证通过仅证明该新增规则下的提案，不应将 `activation_conditions` 写成当前已批准规则。

当前批准的四种条件是**来源完整 EX 执行后**决定是否发事件，不能与旧方案混为一谈。旧提案的历史“现有规则不能值相关激活”结论仅针对当时没有 publication 条件的运行时，加入现行条件后不能继续泛化。

### 当前规则下的示例：来源在进位时传播

用一个无状态节点过滤计数使能，再用每个状态位的 `q=0` 表示该位由 1 翻转到 0 时向高位送进位。

| 节点 | 初值 / 状态 | EX | 传播 |
| --- | --- | --- | --- |
| Q0，使能入口 | 无状态 | `J0K(X0)` | q=1 |
| Q1，最低位 | 0 | `K(Q0)` | q=0 |
| Qi，第 i-1 位，i≥2 | 0 | `K1K(Q(i-1))` | q=0 |

2bit 取 Q0..Q2，8bit 取 Q0..Q8；所有位初值 0，`Yi→Q(i+1)`。

行为：X0=0 时仅入口 Q0 执行，状态位均不执行；X0=1 时 Q0 发布 1，Q1 翻转。某位翻到 1 后停止传播；翻到 0 才发布进位，下一位在该输入处理协议下读取低位 0 并翻转。因此仅实际变化的输出状态位执行。

这个例子的 `q_y` 读取保存在位节点中的计数状态。位节点传播的是“进位为 0”的事件，不是每一位所有变化的数据流；若用途要求每次位变化都向外发数据事件，应另行设计该接口。

本次仅做补充小验证：2bit 8 条、8bit 512 条状态转换全部通过；完整模周期分别执行 6、510 次输出状态位。参考模型、复现脚本与本次报告见本页附件。这些是规则可组合性示例，不是任意重叠输入的证明，也没有宣称全局最少节点或真实运行耗时提升。

## changed / unchanged / rising / falling 由节点组合实现

四种判断无需增加 publication 枚举值。保存旧数据，与新事件数据计算，再使用 `q=1` 发布成立脉冲即可。

| 节点 | 功能 | EX | 初值 / 状态 | 传播 |
| --- | --- | --- | --- | --- |
| Q0 | 新数据事件 | `J0K(X0)` | 无状态 | q=0/1 |
| Q1 | changed，新旧不同 | `J0K(Q0)K(Q5)` | 无状态 | q=1 |
| Q2 | unchanged，新旧相同 | `J0K1K(Q0)K(Q5)` | 无状态 | q=1 |
| Q3 | rising，0→1 | `J0K1K(Q5)J(Q0)` | 无状态 | q=1 |
| Q4 | falling，1→0 | `J0K1K(Q0)J(Q5)` | 无状态 | q=1 |
| Q5 | 保存本次数据为下一次的旧数据 | `J0K(Q0)` | 0 | q= |

`initial_q={"0":["Q5"],"1":[]}`。Q0 的同次事件先通知 Q1..Q4，它们读取 Q5 旧状态；最后通知 Q5 写入新数据。不能把 Q5 写回排在四个判定之前。初始比较也可以令 Q5 初始为 1，但那会改变第一次判断的参照值。

| 旧值 | 新值 | changed | unchanged | rising | falling |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 无 | 1 | 无 | 无 |
| 0 | 1 | 1 | 无 | 1 | 无 |
| 1 | 0 | 1 | 无 | 无 | 1 |
| 1 | 1 | 无 | 1 | 无 | 无 |

表中“无”是不发事件，不是发送数值 0。各判断节点发布的载荷恒为 1；这与“判定成立时传递原数据”是两个可组合步骤。若要同时传数据，应通过判定事件触发转发节点，读取/锁存与本次判定对应的新数据；不得稍后随意读取已被下一次输入覆盖的最新来源。

本次重核：两个旧值初始态，各 256 条长度 8 的输入序列，共 4096 次采样，四种脉冲以及旧值写回均通过，协议为一次 X0 事件排空后再输入下一次。尚未把该局部验证泛化到任意消费者速度或多来源缓存覆盖。

## 计算事件与状态保存分开

### 无状态 Q7 发值，有状态 Q8 保存

Q7 设为无状态并采用 `q=0/1`，它的每次事件都携带本次计算结果；Q8 通过 `J0K(Q7)` 保存最近值。需要观察每次结果的消费者可直接消费 Q7 的事件，但必须对每个事件及时执行，或另有逐项数据保存结构。若目标还在等待其他无状态来源，同源到达槽仍会被后续 Q7 事件覆盖；无状态来源本身不提供无限历史保存。仅消费 Q8 的更新通知后再读取 Q8，也不能还原已覆盖的结果。

原因：有状态来源的历史通知不保存目标计算时的历史可读 q。如果 Q8 已先后写入 1、0，稍后处理两条通知时都读取最新 Q8=0，仍可能丢掉中间的 1。无状态来源的到达值保存在具体目标链接上，具有不同语义。

若同一 Q7 事件需要先与旧 Q8 比较，再写回 Q8，可用低编号比较节点先执行、Q8 后写回。例如局部编号示意：Q6 `J0K(Q7)K(Q8)`、传播 q=1；Q8 `J0K(Q7)`、初值 0、传播 q=。正式可导入模型仍须补齐连续 Q 编号，并满足无状态来源依赖 DAG。

### Q9 保存 Q7 的旧 q

如果本次计算依赖自己的旧结果，可以把运算放在无状态 Q7，把持久值放在状态 Q9：概念示例为 Q7 `J0K(Q9)K(Q0)`、Q9 `J0K(Q7)`，Q0 是无状态输入事件。Q7 从 Q9 读旧数据，然后 Q9 保存 Q7 新结果。

该分解解决了“无状态运算如何读旧状态”的表达问题；若 Q7 可以在 Q9 回写前再次执行，还需要许可 / 确认结构把相邻两次状态转换排序。不能把一个单独的状态分离式当成重入安全证明。

### Q10i 循环许可 / 锁存模式

模式要求：首次输入可启动；每次启动立即占用许可；下一次运算需等上一次 Q9 完成写回的确认；确认后继续取队首数据。确认必须对应实际写回完成，而且即使写回的新旧值相同也能确认，所以作为确认来源的 Q9 不能配置 `q=` 或依赖 changed 才发事件。

这是状态转换消费侧的顺序要求，不能据此禁止输入侧继续进入。多个输入的保存由动态等待区负责。许可、忙标记、有效位、旧状态需要由状态节点或等价的结构状态承载；只把一个节点命名为“无状态触发器 Q10i”并不能凭名称证明这些记忆已实现。
