## 2026-11-05：纠正 JKS 登记与通知轮次的审查前提

依据用户对 S1—S5 的纠正：JKS.trigger 的所有类型均按内部连接结构需要登记；同一 trigger 的事件源整体去重；重复通知只参与触发判定。all／transaction 到齐后任务入队并清空本轮记录，前一轮排队或执行期间的新通知属于下一轮。

| 位置 | 修改前 | 修改后 |
| --- | --- | --- |
| 审查前提与规则说明 | 把登记当成脱离内部连接的任意附加条件，并据此构造冲突 | 撤回相关 S1—S5 质疑；所有登记由实际内部结构需要决定，不将不符合该前提的例子列作设计缺口 |
| 来源去重 | 静态工具仅限制单个数组内重复，存在跨类型重复同源的错误正例 | 按同一 JKS.trigger 的全部登记整体去重；短 ID 与绝对路径指向同一实际 JKI 也视为重复 |
| 触发轮次 | 未完整写明 JKS 到齐后的记录清空时机及后续通知归属 | 到齐即任务入队并清空；不等待前一任务开始或结束，后续通知归下一轮 |

## 2026-11-05：JKS all 与事务失败回滚

用户更新：增加 JKS.trigger.all，全部到齐后触发；transaction 与 all 都等待全部到齐，transaction 的完整执行失败时回滚、取消本次所有计算；其他控制类型或用途按需增加。

| 位置 | 修改前 | 修改后 |
| --- | --- | --- |
| JKS.trigger | 已列 any、transaction 与五类用途，没有显式 all | 增加 all；all／transaction 都要求全部前置通知到齐；用途名按需增加，不固定枚举 |
| 事务结果 | 只明确整体计算后统一传播，未定义失败回滚 | 完整成功保留结果并统一传播；失败撤销本次全部计算造成的 q 变化，取消本次未提交传播 |
| 子结构 | 纳入最外层活动事务的计算与传播范围 | 同时纳入其失败回滚范围，已算完的子结构也不能保留本次部分结果 |
| 冲突旧条文 | “只统一通知、不涉及状态提交”可能被解释为禁止回滚 | 明确回滚结果义务，不指定快照、日志、候选字段或自动重试 |
| 静态检查 | 通用注册数组，缺少 all 专项覆盖 | 增加 all／transaction／按需用途正例及 all 错误数组、引用、路径反例；JKI 仍仅 any/all |
| ASCII 参考工具 | 可能把未支持的 JKS 注册忽略后按普通节点图执行 | 明确限制执行能力为 JKS 空注册／any；合法 all／transaction 结构通过静态检查后仍被明确拒绝执行 |

本条替代历史记录中的事务仅统一传播而无失败回滚的表述。JKI 独立任务行为、递归 members、绝对路径及模块职责边界保持有效。结果为 0、值不变或不满足 publish 都不是执行失败；回滚不扩大到无关输入或其他事务。JKS all 的到达存储、事务回滚具体实现、自动重试与队列故障处理不在本次新增字段或机制。

检查仅证明当前注册格式与已有参考范围：462 次 ASCII 串行输入及原有重叠反例仍保留；新增工具能力拒绝检查用于避免误报 JKS all／transaction 已实现。没有把 JKI.all 的到达验证当作 JKS.all 的执行证明，也没有将静态检查当作事务回滚证明。工厂旧候选状态与失败交接方案继续标记待适配。
