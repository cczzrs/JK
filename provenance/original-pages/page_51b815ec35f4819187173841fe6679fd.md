## 现行规则与实现对齐

JK 节点明确分为三个职责分支：状态决定 q 如何保存、下一次计算从什么状态开始；EX 决定如何计算本次 q；事件决定何时执行，以及完整 EX 结束、提交最新 q 后是否传播。分类只依据 initial_q 成员身份，有状态节点允许 EX 以 J0 开头；无状态节点不在 initial_q 中，EX 必须以 J0 开头。

传播条件共四种：`q=0/1` 默认每次完成均传播；`q=0` 只传播本次完整结果 0；`q=1` 只传播本次完整结果 1；`q=` 永不传播且仅用于有状态节点。条件中的 q 是本次 EX 最新结果，不是变化检测。未传播仍完成计算和状态更新；同值结果也分别判断条件，已入队事件不在出队时重新过滤。传播条件的原生 JSON 编码、默认规范化、哈希迁移及执行器接入尚需落实，参考设计使用的 `publication` 不能被视为已经定稿的原生字段。

输入与 Q 的 fan-out 是构建和搜索时的覆盖约束：每个输入应被使用，每个 Q 应供其他 Q 或 Y 使用，避免无效或孤立结构。这些构建策略与核心的 ex 语法、来源及到达规则分别承担职责。布局维度与三维坐标用于展示，不改变计算语义，也不能作为模型智能或硬件性能证据。

## 训练参数与训练入口

训练路径是 `连续选择分数 → 离散 J/K 和来源 → 有序 ex 与输出绑定 → 严格快照`。可学习的 logits 是训练过程中的选择参数；导出模型主要保留离散结构及指定 q。q 在运行中更新，表示记忆或中间计算状态，不会因为被保存就自动成为数值权重。

当前训练入口包括 `training.ste`、`training.random_structure`、`training.guided_structure` 和 `training.hybrid`，分别用于选择参数的梯度训练、随机结构搜索、基于实际 loss 的候选改进及混合搜索。STE 提供可优化的近似路径，不能据此推断任意任务会收敛或泛化。

## 模型池组合与冻结

`jk_group_pond` 可加载多个已有 JKGroup。运行实例分别维护状态；冻结组合模型时为实例分配独立 Q 编号区间，重写输入、内部 Q 和输出引用，形成标准 X/Q/Y 快照。复用前必须明确各模型的位宽、初始状态和输入时序契约。

## 优化实现与现行规则衔接

源码基线的 `optimizer.optimize_expressions` 对单节点枚举完整的 `旧 q + 所有参数 → 新 q` 真值表，再搜索更短的等价 ex。现行规则要求保留参数集合、传播条件及由 initial_q 决定的有状态/无状态分类；以是否 J0 开头推断分类的旧约束必须修正。有状态节点允许 J0 开头，无状态节点优化后仍须以 J0 开头。J1 和 K0 是恒等操作，可在满足证明条件时移除；结果仍必须非空且至少引用一个 Xi 或 Qi。优化后要重新检查节点分类、来源约束、触发行为和事件发布行为，不能只因最终数值相同就接受删边或改变事件来源。

这类证明限定在单节点、既定来源集合和分类之内。它不证明整个网络节点数最少，也不自动证明任意重连、删边、常量折叠或跨轮调度都保持完整事件行为。优化后还应核对最终输出、状态序列、执行次数、到达条件和待消费缓存。达到枚举限制必须报告未完成，不能视为已经证明最小。

现行规则要求：所有 Q 的 ex 非空并至少引用一个 Xi 或 Qi；读取 q 不触发来源节点执行；所有 Qi_q 引用在目标执行时读取来源最新的实际 q，旧通知事件不得用历史值回滚计算可见 q；优化不能产生或保留纯常量参数节点及空 ex 节点。节点分类、四种传播条件、来源事件 FIFO 与目标立即原子执行也必须遵循规则页。源码基线已拒绝空 ex，但仍包含 `group.py` 的纯常量节点按需执行路径；`optimizer.fold_constants` 仍采用旧的常量 Q 折叠及输出代表节点策略。后续源码同步需逐项验证，不能将本页模块说明、历史验证或独立参考执行器结果视为项目核心已完成同步。

## 从需求到可复用模型的流程

以下流程包含现行规则要求；纯常量节点拒绝、取消读取时执行、initial_q 分类、四种传播条件及相应优化与序列化约束，需要结合实际代码逐项完成和定向验证。动态存储另需结构扩缩、逐项捕获与并发到达的验证，不能由固定拓扑功能验证替代。

1. 明确输入位宽、输出编码、功能公式、初始 q、输入时序和期望输出；需要位级算术时约定符号及位序。

2. 配置模型并选择已验证的模型池；没有可复用模型时使用空池。

3. 用 model.build 提交完整设计，或用 training 入口生成候选结构。

4. 校验每个 Q 的 ex 非空且至少引用一个 Xi 或 Qi，再检查 initial_q 分类、来源约束、到达 DAG、传播条件合法性、对外输出映射及实际成本。`q=` 只允许有状态节点；内部状态无需为了观察或扩展而全部暴露为 Y。

5. 优化表达式及可证明等价的常量值，拒绝产生纯常量参数节点、空 ex 或改变触发行为的候选，检查证明报告及生成的新快照身份。

6. 对最终快照执行 model.verify；小规模组合任务覆盖有效输入组合，有状态任务按设计顺序验证多轮输出和状态。

7. 同时检查重复相同值输入、一次输入的多次执行、四种传播条件、未收齐的跨轮缓存、有效数据为 0 的递交，以及重置和重载边界。对动态等待区还须检查上一项处理未结束时的新输入、连续同值独立入队、扩缩和回收、FIFO 顺序、确认前数据保持与确认后逐项推进；未覆盖的交错与生命周期应明确标为待验证。

8. 检查 passed、mismatch_count、checked_count 与参考样本数，确保验证针对实际要复用的快照。

9. 功能通过后命名并提升到永久模型池，供后续组合使用。

动态等待区的正式需求不设置固定总容量，也不要求上游等到本次内部处理结束后才提交下一项。每次到达须在入口独立保留该次数据，再由存储结构增加或分配存储节点并挂接队尾；连续同值也必须成为独立队列项。锁存与确认只控制消费端依次取用，不能阻止输入端继续保存。节点分配、挂接、队首推进、回收/复用和并发到达顺序尚需明确实现机制；现行 J/K EX 未定义动态节点创建指令，不能把固定拓扑原型或宿主数组缓存宣称为完整纯 JK 动态存储实现。

43 节点参考原型的对外映射已经确定为 `Y0→Q39` 数据递交、`Y1→Q41` 有效消费确认已处理。Q32 锁存当前递交数据但采用 `q=` 不发布；Q38 发出递交许可；无状态 Q39 被触发后读取 Q32，并以 `q=0/1` 发出携带数据的事件。Q31～Q36 的状态及 Q40 请求接受通知属于内部结构。重复数据必须按事件次数消费，不能仅比较 Y 最近值；当前有限模型的容量拒收和入口串行限制属于其不足，不是正式动态模式的需求。

设计详见 [JK锁存与动态等待区](https://chatgpt.com/space/page_e5e9e0d2df6481919ab152dec8208cde)；有限模型与完整 JSON 见 [JK异步结构静态原型](https://chatgpt.com/space/page_49e5ba0ff7e88191b27dee5f9778d2dc)。

冻结卷积中的权重是外部训练所得的数值常量，和 DynamicSelector 的来源选择参数不同。当前标准快照输入输出上限为 216 位，服务动态训练配置的节点容量上限为 512；该训练配置上限不应推广为所有 JKGroup 或卷积编译结构的统一上限。
