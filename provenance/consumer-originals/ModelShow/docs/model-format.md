# 模型格式与执行语义

[返回项目入口](../README.md) · [操作说明](usage.md)

规则主来源：[JK规则与设计](https://chatgpt.com/space/page_1cee9c7aae188191be3608cbf94fb889)及[ModelShow设计文档](https://chatgpt.com/space/page_f0054dda6f3c81918b9985ba46e2f092)。本次按 2026-10-02 读取的现行内容实现；旧项目行为不作为规则例外。

## 节点的状态、EX 与事件

| 分支 | 执行约定 |
| --- | --- |
| 状态 | 仅由 `initial_q` 成员身份分类。有状态 Qi_q 保存 q；无状态 Qi_J0 每次从 `J0` 清零计算，并保留当前结果供输出读取 |
| EX | 非空、从左到右原子执行 `J(x): q ← q AND x`、`K(x): q ← q XOR x`；至少引用一个 Xi 或 Qi |
| 事件 | 非常量来源事件触发，或等待全部不同 Qi_J0 来源；完整 EX 提交 q 后判断传播条件 |

`initial_q["0"]`、`initial_q["1"]` 中的节点必须只出现一次。有状态节点可以以 `J0` 开头，加载时不会提前执行或清零；未声明的无状态节点必须以 `J0` 开头。

允许 token：`J0`、`J1`、`K0`、`K1`、`J(X0)`、`K(X0)`、`J(Q0)`、`K(Q0)` 等连续拼接。拒绝空白、别名、嵌套、空 EX，以及仅含字面量的完整节点（例如 `J0`、`J0K1`、`K1`）。字面量可以出现在具有 Xi/Qi 来源的 EX 中。重复来源只形成一次来源通知关系，但每个 J/K token 都分别求值、统计并显示连线。

## 来源事件 FIFO

1. 发送先校验本次全部匹配输入，再按 Xi 编号把来源事件追加队尾。发送不提前替换整行 X 值。缺失输入保持旧可读值，多余字段忽略；匹配值必须是数字 0 或 1，错误时整次不入队。
2. 单步消费一个来源事件。Xi 事件更新该 Xi 的可读值；初始 Xi 为 0。按目标 Q 编号升序通知直接消费者，同一个来源可能在这一单步内触发多个完整节点求值。
3. 目标没有 Qi_J0 来源时，每次非常量来源事件执行一次完整 EX，只允许读取编号更小的 Qi_q。
4. 目标有 Qi_J0 来源时，只把不同 Qi_J0 的到达值写入目标自己的链接缓存。Xi 更新、Qi_q 通知不触发此目标。全部 Qi_J0 到齐后锁存缓存、读取当前 Xi 和 Qi_q 的最新实际 q、求值并清空该目标集合；此时允许任意编号 Qi_q。
5. 每次完整 EX 立即提交 q，再判断传播条件。满足时把一个 Q 来源事件追加队尾，已经入队的事件出队时不重新过滤。
6. Qi_q 旧通知只用于触发，不能用历史携带值回滚 q。Qi_J0 使用该事件的携带值。同值事件也逐次处理。
7. FIFO 排空后读取 `q_y` 绑定 Q 的当前 q 作为正式输出。队列未空时界面显示当前中间值；最近发布值单独显示。未发布不等于发送 0，也不妨碍 `q_y` 读取最新 q。

Qi_J0 同源重复到达在屏障收齐前覆盖原槽，未收齐槽跨发送保留。只有 `Qi_J0 → 目标` 边必须构成 DAG；状态读取、Xi、常量和输出边不参与该检查。运行 FIFO 保存通知顺序，不提供逐项业务数据历史。

初始化和重载设置有状态初值、无状态当前值 0、Xi 当前值 0，清空队列、缓存、发布记录和计数；不主动计算或发布。合法 Yi 即刻可读绑定 Q 的初始值，异常绑定为不可读。

### 四种传播条件及本项目编码

本次将空间已确认的语义落实为 `nodes[].propagation`：

| JSON 值 | 传播行为 | 适用分类 |
| --- | --- | --- |
| `"q=0/1"`（省略时默认） | 每次完整 EX 后发布 | 有状态、无状态 |
| `"q=0"` | 仅最终结果 0 发布 | 有状态、无状态 |
| `"q=1"` | 仅最终结果 1 发布 | 有状态、无状态 |
| `"q="` | 永不发布，仍保存 q | 仅有状态 |

此字段采用空间现行编码。其它条件（如 `changed`）不能作为此字段的值；需通过合法 JK 结构组合。传播条件在完整 EX 结束时只检查一次，不比较前后 q；被过滤的 Qi_J0 事件不进入下游到达集合。

### 两个行为示例

```json
{
  "name": "逐 Xi 事件累计奇偶",
  "nodes": [{"id": "Q0", "ex": "K(X0)K(X1)"}],
  "initial_q": {"0": ["Q0"], "1": []},
  "q_y": [{"Y0": "Q0"}]
}
```

发送 `{"X0":1,"X1":1}`：消费 X0 时读取 `(1,0)`，Q0 从 0 变 1；消费 X1 时读取 `(1,1)`，Q0 保持 1。两次求值、两次发布、四次 EX 操作；继续消费两个 Q0 发布事件后排空，Y0 为 1。将整行只计算一次会错误得到 0。

若改为 `ex:"K(X0)"`、`propagation:"q="`，初值 0，依次发送并排空 1、1、0，则当前 Y0 为 1、0、0，节点求值三次，Q0 发布次数为零。

## 模型结构、校验与身份

核心字段是 `nodes`、`initial_q`、`q_y`。公共文件/JSON 导入及模型池读取要求完整合法快照，包括 `name`、统计、容量、端口、两种指纹、`format` 和 `created_at`；错误时保留当前模型，不重新计算指纹掩盖错误。内部 `compileModel` 可诊断简式结构和异常节点，`serializeModel` 用于明确的结构编辑与快照生成。上面的示例只说明执行结构，直接导入前须补全规范字段。

- `nodes` 必须按顺序使用连续 `Q0..Qn`。固定 ID 不接受尾缀、前导零或跳号。独立 `tag` 只用于显示，必须以英文字母开头，其余为字母/数字；EX、initial_q 和 q_y 只引用固定 ID。
- `q_y` 按连续 Y0 起始排列，绑定已有 Q。多个 Y 可绑定同一 Q。输入及输出位宽各不超过 216。
- `inputs`、`outputs` 必须是有序连续的身份映射。合法声明的未引用 Xi 仍是输入端口；内部简式结构未声明输入时由最大 Xi 引用推导连续端口。输入引用不得超出声明宽度。
- `jk_bits` 是实际节点数；`jk_bits_max` 不小于实际数量。`ex_source_max/sum` 统计非常量参数使用位置（重复引用也计数）；`ex_operation_max/sum` 统计全部 J/K token。
- `format` 仅为标记，不选择旧语义或拒绝另一版本。导出补全格式、时间、端口、统计与指纹。
- 公共导入拒绝任一节点或元数据错误。内部诊断保留异常行、隔离其依赖，便于详情展示；节点顺序、端口、整体统计或指纹错误阻止整个模型运行。结构无效不能导出为规范快照。

指纹采用 UTF-8、递归键排序、无空白、保留规范数组顺序的 canonical JSON：

```text
normalized_nodes = nodes（省略显式默认 propagation，其它节点字段保留）
stateful_ids     = initial_q["0"] 与 initial_q["1"] 合并后按 Q 编号排序
md5             = MD5({nodes: normalized_nodes, initial_q, q_y})
format_md5      = MD5({nodes: normalized_nodes, q_y, stateful_ids})
```

显式默认 `q=0/1` 在规范化时省略，因此缺省与显式默认具有相同指纹；非默认条件参与两种指纹。当前公式保留节点全部其它字段，因此节点 `tag` 及自定义字段也参与指纹；顶层名称、时间、outputDisplay 等不参与。仅改变已保存 q 的 0/1 分组会改变 md5，不改变 format_md5；改变有状态成员集合会改变 format_md5。

旧指纹迁移仅接受完整合法、所有节点均未提供 propagation、且旧 md5 与旧 format_md5 同时匹配的快照。旧公式分别为 `MD5({nodes,initial_q,q_y})` 和 `MD5({nodes,q_y})`。成功后克隆并规范化为现行指纹，读取不会直接改写磁盘或远程模型池；伪造指纹、混用新旧格式及带传播字段的旧指纹均拒绝。

下载和画板导出重新计算统计与指纹；有效原模型仅修改画板不会改变计算指纹。结构编辑后不能继续沿用旧 MD5 冒充已校验。`created_at` 使用 UTC 小时加 Unix 纳秒格式，首次生成精度来自本地毫秒时钟。

## 快照与恢复边界

下载当前已加载模型以及“导出模型及画板配置”保存当前有状态 q 和已应用画板配置，重新生成统计、指纹与时间。只改变原有有状态成员的 0/1 分组，不改变分类；加载后恢复保存 q，不提前执行。编辑区未导入的草稿保留自身 initial_q 和 outputDisplay，不混入当前运行模型的 q 或画板。明确编辑计算结构时重新生成派生字段；仅伪造指纹或元数据的草稿仍拒绝。

标准快照不保存已读取 Xi、无状态运行结果、未收齐 Qi_J0 缓存、待处理来源 FIFO 和播放进度，因此不能一般性继续未完成现场。动态等待区要求逐项保存、持续接收、按需分配/回收；空间尚未规定动态节点创建、连接、释放和完整恢复格式，本实现不把执行 FIFO 或有限静态原型称为动态存储。

## 统计与展示边界

网络概览 EX 总量是已解析模型的静态 token 总量。节点求值次数/页脚 EX 累计仅在完成求值时增加；消费一个来源事件可以触发零个、一个或多个节点。来源事件消费次数单独统计。历史最多保留 400 条、显示最近 60 条，裁剪历史不会删逻辑队列或缓存。

队列达到 10,000 项时暂停自动消费并阻止新增发送，可单步消费或重载；原子通知产生的新事件不截断。这是浏览器运行保护，不是动态等待区的业务总容量。动画只展示已消费的传播记录，不再次执行计算；静默提交 q 仍更新 Yi 画板，但不伪造传播动画。
